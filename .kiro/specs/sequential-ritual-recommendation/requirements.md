# Requirements Document: Sequential Ritual Recommendation System

## Introduction

The Sequential Ritual Recommendation System is an AI-powered feature that analyzes user behavior sequences to detect ongoing Vietnamese cultural rituals and ceremonies, then recommends missing ritual items based on traditional customs. The system combines user action tracking with cultural pattern matching to provide contextual, explainable product recommendations that respect Vietnamese traditions.

## Glossary

- **Ritual Pattern**: A predefined sequence of user actions that indicates a specific Vietnamese ceremony (e.g., Đầy Tháng, Tết, Lễ Cúng Tổ Tiên)
- **Action Sequence**: A chronological list of user interactions (viewing products, adding to cart, browsing categories)
- **Missing Items**: Products that are traditionally required for a detected ritual but not yet in the user's cart
- **Confidence Score**: A numerical value (0-1) indicating the probability that the detected ritual pattern matches the user's actual intent
- **System Report**: Structured explanation of why specific items are recommended, including ritual context and cultural reasoning
- **Gemini API**: Google's AI service used for natural language processing and explanation generation
- **BE-AI (Backend Strategist)**: Backend component that defines ritual patterns, cultural rules, and required items; provides pattern matching logic and recommendation data
- **FE-AI (Frontend Advisor)**: Frontend component that calls Gemini API to generate human-readable explanations and cultural context for recommendations
- **PrefixSpan-inspired Matching**: Sequential pattern mining technique adapted for ritual detection
- **Ritual Manifest**: Backend configuration file containing all ritual patterns, action sequences, required items, and cultural metadata
- **Recommendation Payload**: Data structure returned by BE-AI containing matched ritual, missing items, confidence score, and raw reasoning
- **Explanation Payload**: Human-readable text generated by FE-AI (via Gemini) that explains recommendations in cultural context

## Requirements

### Requirement 1

**User Story:** As a customer, I want the system to understand what ritual I'm preparing for based on my browsing and shopping behavior, so that I receive relevant product recommendations without explicitly stating my intent.

#### Acceptance Criteria

1. WHEN a user performs a sequence of actions (viewing ritual items, adding products to cart) THEN the system SHALL analyze the sequence against known ritual patterns
2. WHEN a ritual pattern is detected with sufficient confidence THEN the system SHALL identify the specific ritual type (e.g., Đầy Tháng, Tết, Lễ Cúng)
3. WHEN a ritual is detected THEN the system SHALL compare detected ritual requirements against items already in the user's cart
4. WHEN missing items are identified THEN the system SHALL retrieve product recommendations for those items from the catalog
5. WHEN the user's action sequence does not match any known ritual pattern THEN the system SHALL not generate recommendations and maintain normal browsing experience

### Requirement 2

**User Story:** As a customer, I want to understand why specific products are being recommended to me, so that I can trust the AI's suggestions and learn about traditional customs.

#### Acceptance Criteria

1. WHEN a recommendation is generated THEN the system SHALL provide a human-readable explanation of the ritual context
2. WHEN an explanation is provided THEN the system SHALL include the ritual name, cultural significance, and why each recommended item is traditionally required
3. WHEN displaying recommendations THEN the system SHALL show a confidence score indicating how certain the system is about the detected ritual
4. WHEN the user requests more details THEN the system SHALL provide expanded cultural context and traditional usage of recommended items
5. WHEN recommendations are displayed THEN the system SHALL cite traditional sources or cultural references to support the recommendations

### Requirement 3

**User Story:** As a system administrator, I want to define and manage ritual patterns and their associated required items, so that the recommendation system stays accurate and culturally appropriate.

#### Acceptance Criteria

1. WHEN a ritual pattern is defined THEN the system SHALL store the pattern as a sequence of action types and required products
2. WHEN a ritual is created THEN the system SHALL assign a confidence threshold for pattern matching
3. WHEN ritual data is updated THEN the system SHALL validate that all required items exist in the product catalog
4. WHEN a ritual pattern is modified THEN the system SHALL not affect existing user sessions until the next action sequence analysis
5. WHEN ritual patterns are stored THEN the system SHALL persist them in a structured format that supports efficient sequential matching

### Requirement 4

**User Story:** As a developer, I want the recommendation system to be explainable and auditable, so that I can debug issues and understand how recommendations are generated.

#### Acceptance Criteria

1. WHEN a recommendation is generated THEN the system SHALL log the matched pattern, confidence score, and reasoning
2. WHEN a recommendation is generated THEN the system SHALL include metadata about which actions triggered the pattern match
3. WHEN the system analyzes an action sequence THEN the system SHALL record intermediate matching steps for debugging
4. WHEN recommendations are displayed to users THEN the system SHALL include a system report showing the matching logic
5. WHEN the system fails to match a pattern THEN the system SHALL log why the sequence did not match any known rituals

### Requirement 5

**User Story:** As a customer, I want recommendations to be timely and contextual to my current shopping session, so that suggestions appear when they're most relevant.

#### Acceptance Criteria

1. WHEN a user performs an action THEN the system SHALL analyze the updated action sequence within 2 seconds
2. WHEN a new ritual pattern is detected THEN the system SHALL display recommendations in real-time without requiring page refresh
3. WHEN the user adds an item to cart THEN the system SHALL re-analyze the sequence and update recommendations if the ritual context changes
4. WHEN the user navigates away from ritual-related products THEN the system SHALL clear recommendations and reset pattern detection
5. WHEN multiple ritual patterns could match THEN the system SHALL prioritize the pattern with the highest confidence score

### Requirement 6

**User Story:** As a customer, I want the system to respect my privacy and not make assumptions about my personal beliefs or practices, so that recommendations feel helpful rather than intrusive.

#### Acceptance Criteria

1. WHEN recommendations are generated THEN the system SHALL present them as suggestions, not requirements
2. WHEN a user dismisses a recommendation THEN the system SHALL record the dismissal and reduce future recommendations of that type
3. WHEN a user explicitly indicates they're not interested in a ritual THEN the system SHALL disable pattern detection for that ritual in the current session
4. WHEN recommendations are displayed THEN the system SHALL include an option to hide or dismiss them
5. WHEN the system detects a ritual pattern THEN the system SHALL not share this information with third parties or use it for non-recommendation purposes

### Requirement 7

**User Story:** As a backend developer, I want to define ritual patterns and cultural rules in a centralized manifest, so that the system can efficiently match user behavior against known rituals.

#### Acceptance Criteria

1. WHEN the system starts THEN the BE-AI SHALL load a Ritual Manifest containing all ritual patterns, action sequences, and required items
2. WHEN a ritual pattern is defined THEN the manifest SHALL include action type sequences (e.g., [ViewMamCung, AddToy, ViewNguQua])
3. WHEN a ritual is configured THEN the manifest SHALL specify required product categories and specific items for that ritual
4. WHEN the BE-AI receives an action sequence THEN the system SHALL match it against patterns using PrefixSpan-inspired algorithm
5. WHEN a pattern matches THEN the BE-AI SHALL return a Recommendation Payload containing ritual name, missing items, confidence score, and matching metadata

### Requirement 8

**User Story:** As a frontend developer, I want to call Gemini API to generate natural language explanations for recommendations, so that users understand the cultural context and reasoning.

#### Acceptance Criteria

1. WHEN the FE-AI receives a Recommendation Payload from BE-AI THEN the system SHALL call Gemini API with ritual context and missing items
2. WHEN calling Gemini THEN the system SHALL provide the ritual name, cultural significance, and list of missing items as context
3. WHEN Gemini returns a response THEN the FE-AI SHALL format it as an Explanation Payload with human-readable text
4. WHEN the Explanation Payload is generated THEN the system SHALL include why each item is traditionally required for the ritual
5. WHEN Gemini API fails THEN the FE-AI SHALL fall back to a predefined template explanation without blocking the recommendation display
